# 自动发现与续跑

目标：用户无需逐篇提供链接；一次调用自动完成发现、阅读、提取和待审核交付。浏览器与网站可访问性是运行前提，不将访问失败伪装成零案例。

Chrome 初始化失败且工具提示可重试时，最多重试一次。仍失败则报告具体阻塞；用户未要求仅限 Chrome 时，可披露后使用可用网页搜索/读取工具完成资料整理，manifest 记录 requested_method 和 actual_method。不能将降级结果称为 Chrome 试跑成功；用户明确要求只用 Chrome 时保存阻塞状态，不改用其他方式。

## 1. 自动规划

- 沿用用户明确范围，否则使用 SKILL.md 默认范围和预算。
- 读取输出目录的既有 manifest、queue、candidates；在项目内可同时读取 data/cases.json。第一次运行没有历史就直接开始。
- 将已有记录按航司、事件、原因、回应阶段与结果归类，只用有证据的标签。优先缺少的场景，轮换延误、取消、拒载，不将缺少大额赔偿当作缺口。
- 首批无历史时从“航班取消后的改签、照料、退款或明确拒绝”开始，不要求特定航司，不只搜成功结果。
- 输出本批范围与预算的简短说明后开始，不为确认默认值停下来。

## 2. 生成查询与发现帖子

先用一个具体查询进入搜索结果，观察后再决定下一条，不展开航司×事件×结果的穷举查询网格。可按实际发现的问题调整措辞，始终受全批查询预算限制。

查询构成：来源域名 + 事件词 + 可选航司/结果词。示例仅用于生成搜索查询，不代表真实存在的帖子：

- `site:uscardforum.com 航班取消 改签`
- `site:uscardforum.com 航班延误 拒绝 报销`
- `site:uscardforum.com denied boarding voucher`

在 Chrome 读取搜索结果或论坛站内结果，获取实际出现的链接；不得猜测帖子 ID 或伪造楼层 URL。搜索摘要只支持候选发现。优先具体第一手经历、有处理更新和可定位时间航线的帖子，同时保留拒绝、部分处理和未结束案例。

日期筛选主要限制发现范围；搜索引擎日期可能是发帖或更新日期，不能据此认定事件发生时间。一个查询没有合适结果可调整一次重点或换预定主题；不无限改写同义词。

## 3. 候选队列与阅读

每个队列项包含：`url`、`discovered_by_query`、`state`、`reason`、`last_observed_at`、`resume_locator`、`linked_dp_ids`。state 为 queued/reading/extracted/followup/excluded/blocked。

打开之前先与已有 URL、主题 ID 比对。阅读原帖后核对事件 R 项和航司回应 R 项；O 项缺失不触发淘汰或无限搜索。追踪作者后续，记录读到的楼层及未读部分。楼层定位只能来自实际页面；无法取得永久链接时保存主题链接和可复核定位说明。

已有初始方案但无最终更新的 DP 可以交付；若值得以后追踪，队列记 followup，并写明缺哪项更新。无法访问的页面记 blocked，继续其他候选；全站受阻时交付阻塞报告，不反复尝试访问同一障碍。

## 4. 保存与续跑

每完成一个主题，将提取结果和队列写入本批目录，避免只在最终回复里保存进度。保留既有 DP ID；更新记录不覆盖原证据。恢复时先核对队列与已保存候选，防止中断造成重复。

用户说“继续”时：先处理未完成的 queued/reading，再检查明确需要追踪的项目，剩余预算用于新发现。已完成记录无新更新线索时不反复整帖读取。新批次保存上一批位置与本批实际查询；不把沿用旧数据算作新增收集。

精确重复跳过；疑似重复保留供审核。同一主题中多个旅客仍可分别提取。不得为达到数量目标将一个人的连续处理拆成多个 DP。

## 5. 运行结束

达到任一预算、可访问候选耗尽或浏览能力不可用时结束本批，保存停止原因和队列。交付：新发现链接数、实际读取主题数、新增 DP 数、更新 DP 数、R 不全数、重复数、阻塞数，以及待审核文件路径。

预算不足或无合适记录都允许少于 5 个候选。默认人工审核仅发生在候选是否晋升产品库这一环，不要求用户逐篇选择要搜索或阅读的帖子。
