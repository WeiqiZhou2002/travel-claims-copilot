# 修复记录（2026-09-26）

审查基线见 REBUILD_REVIEW.md。本轮是原有应用上的可靠性修复，不代表整套重构或法律规则库完成。

## 已实现

- 机场阶段不再要求尚未发生的最终到达时长；解析时排除“提前到机场”的时长，识别显式实际承运人、事件否定表达，不从拒载自动补造超售原因。
- 新增 acceptedAlternative，区分自动改签和主动接受替代方案。
- 增加单项请求判断。已完成行程的未使用机票退款请求、自愿让座的非自愿拒载话术被排除。未知资格保留待确认状态，话术不再断言会员号已关联、已经附上证据或没有接受任何替代安排。
- 建议、话术筛选以及已完成行程的行动清单使用请求判断；已排除退款时不再套用退款证据清单。
- 官方依据评估不再默认先裁到前三条；相似案例排除合成记录、明确相反的原因/让座类型，没有航线时避免跨航司借用结果。无匹配真实案例明确返回空结果。
- 两个 API 按实际流入字节限制请求体，增加读取超时、事实字段长度/数组上限；结构化字段和保留的风险上下文也经过范围检查。
- Intake 增加单进程每分钟 60 次和最多 4 个并发调用的保护；限制模型输入与输出预算，记录不含原文的故障类别和延时。
- 页面增加请求取消/版本保护、失败时恢复输入、事实修正、主动勾选的本地草稿恢复、本地结果反馈及 JSON 导出。分析请求不再重复发送整段聊天历史。

## 验证

- 111 项自动化测试通过，包含 13 项新增审查回归测试；数据校验、TypeScript、ESLint 通过。
- 生产构建通过。浏览器使用关闭 LLM 的本地路径检查短延误完成场景、事实修正、重新分析、刷新恢复及新建案件清空状态。
- 未执行真实外部 LLM 调用、分布式负载测试或全部地区规则的法律审定。

## 仍需后续实现

- 事实出处、显式冲突与修订记录、统一生成的 schema；当前仍有关键词抽取和字段优先级合并，不能保证所有措辞正确。
- 完整分项资格规则、跨制度适用、来源版本/时效管理与人工复核；当前 pending 条件不是已确认资格。完成行程但无法提供延误分钟数的追问仍需改为可声明未知。
- 多实例共享配额和成本上限；现有内存限制会随进程重启清空，不能替代网关配额。
- 增加经核验的真实案例；当前知识库不足，不用合成案例补齐。客户端保存的事实及风险上下文可被修改，不能当作服务器可信案件记录。
- 手机端全面验收、自动化浏览器回归、各模型和双语的事实冲突评测。

## RAG 接入位置

保留 lib/retrieval.ts 作为检索边界。建议流程是：结构化事实 → 地域/承运人/事件/来源类型过滤 → 政策原文和真实案例检索 → 单项条件检查 → 带可核对引用的解释与话术。

先为现有 JSON 增加人工审定的原文片段、条款定位、适用日期与复核信息，再用真实问题评估召回。需要语义检索时增加关键词与向量混合召回；数据库和向量存储不应替代规则判断。官方政策、企业承诺和社区经验保持独立来源类型；来源内容只能作为资料，不能作为模型操作指令。

本轮没有新增 embeddings、向量库或 RAG 生成调用。现有流程是确定性检索与模板输出，LLM 主要用于事实抽取。
